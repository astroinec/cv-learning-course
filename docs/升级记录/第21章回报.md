纠正原讲义的地方：
1. 第 5 节原文“Phong / Blinn-Phong 高光：加上 (n·h)^shininess 项”，把两个模型写成了同一个式子。(n·h)^s 是 Blinn-Phong，Phong 是 (r·v)^s。按公式算（不是渲染实测），同样的指数下 Blinn-Phong 的高光按角度宽一倍（s=32 时 23.76° 对 11.88°），要一样宽指数约取 4 倍（128.7）。正文已改，并加了说明框。
2. 第 4 节原文“屏幕空间直接线性插值会在大三角形上产生纹理扭曲”。实测误差由顶点 w 的最大值与最小值之比 r 决定，和三角形在屏幕上的大小无关：正对相机、占 14792 个像素的矩形误差是 2.8e-15；r=1.63 时 v 的最大误差 0.122，r=4.0 时 0.333，和 (sqrt(r)-1)/(sqrt(r)+1) 到三位有效数字相同。正文已改成“在顶点深度相差大的三角形上”。
3. README 原文“本章用时建议 12–20 小时（OpenGL 选做部分另计）”，按 course.json 改成速通 3、标准 15、深挖 24 小时。
以下三条原文没有错，原样保留，讲义里补了条件和量级：
4. “边上的点可以算在内”：这是作业的约定。实测顶点在整数坐标的网格上，4096 个像素里有 512 个（12.5%）被两个三角形各画一次；只写深度时没有后果，累加类的渲染会多算。
5. “数值误差累积后不再正交”：float32 连乘一百万次后 R^T R 与单位阵最大差 0.0061，float64 是 6.7e-11。
6. 第 4 节第 1 步“计算三角形的包围盒，只遍历盒内的像素”：参考实现没有做包围盒，每个三角形都算整幅图。讲义里写明了这一点。
其余能量化的原文说法实测都成立：z=-n 映射到 -1、z=-f 映射到 1；NDC 的 z 在屏幕空间线性插值正确（最大差 4.4e-16）；两种相机约定差 y、z 取反（转换后和 OpenCV 约定的投影最大差 1.27e-13 px）；near 从 0.1 改成 0.001，最小可分间隔变成 100 倍。

新增的重要结论：
1. 矩阵顺序：模型矩阵内部写成 S R T，300 个随机场景里 96.8% 的顶点仍在视锥内，偏差中位数只有 15.6 px（画面宽 240），最难发现；P、V、M 之间写错（P M V、V P M、M V P）偏差中位数 238.2 到 511.5 px。
2. 相机约定：OpenCV 的位姿不转换就交给 to_screen，300 个位姿里 8 个顶点全部是 NaN；不检查 w 时是绕主点左右镜像，偏差中位数 157.1 px，和第 7 章实测数字.json 里的 157.1 px 相同（用的是同一批位姿）。只把 z 取反是上下翻转（150.0 px）；用对称视锥不管主点偏 7.28 px；主点不加 0.5 时渲染结果整体偏约半个像素（200 个矩形的质心差 (-0.5, -0.49) px，加 0.5 之后 (0.05, 0.0) px）。
3. 深度：far 从 100 加到 10000，24 位深度缓冲在距离 50 处的最小间隔是 0.001489 对 0.00149，几乎不变；near 才是决定因素。实测贴片高 0.01、16 位深度时，near 从 0.1 改成 0.001，贴片上分不开的像素从 0% 变成 90.0%。
4. 共享边：顶点在整数坐标时，“边上算在内”重复 512 个像素、“边上不算”漏 512 个、左上规则每个像素正好一次；顶点是随机浮点坐标时，50 个网格 156800 个像素里三种规则没有差别。按左上规则实现作业会被验收判错（28 个像素对 36 个）。
另外两条：法线直接乘模型矩阵，缩放 2:1:1 时方向最多错 36.87°，椭球的平均亮度低 23.1%；相机在立方体内部时，作业“丢掉含后方顶点的三角形”的做法平均缺 39.8% 的画面，不检查 w 则平均 38.5% 的像素深度是错的。
