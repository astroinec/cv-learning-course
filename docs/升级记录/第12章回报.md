纠正原讲义的地方：
1. 12.9 原文“把大图切成有重叠的小块，分别预测，再在重叠区平均概率或加权融合”。实测（1 个网络、2 张 256×256 的图、切成 64×64 的块）：每块多读 16 px 上下文时，只保留每块中央和整图推理没有一个像素判定不同，重叠处直接平均还有 81 个像素不同（多读到 32 px 仍是 81 个，多读 16 到 32 px 时最大概率差在 0.64 到 0.75 之间），按离块边距离加权平均是 9 个（多读 32 px 时 5 个）。原句已改成三种做法并列，并注明实测里只保留中央最接近整图推理。
2. 12.4 原文把“选择能被 stride 整除的 kernel，如 kernel=2,stride=2”列为避免棋盘效应的办法。实测：覆盖次数确实变均匀（k=2,s=2 都是 1；k=3,s=2 是 1、2、4），但随机初始化、常数输入下，输出按 2×2 四个位置分组的平均值极差（相对平均幅度）k=2 是 2.603，k=3 是 2.731，k=4 是 2.56，同一量级；双线性上采样加卷积是 0。原句后加了括号说明它只消除覆盖不均这一个来源。训练之后的情况没有测。
3. 12.6 原文“两者排序一致，但数值不同，不能混报”。这只对同一对掩膜成立。脚本算的例子：模型甲两张图 IoU 0.92、0.1，模型乙 0.5、0.5，平均 IoU 甲 0.51 高于乙 0.5，平均 Dice 甲 0.57 低于乙 0.667。原句改成“对同一对掩膜，两者排序一致……”。
4. 12.7 原文“训练前不要手动 sigmoid，否则会重复压缩并影响数值稳定性”。算出来不只是稳定性问题：sigmoid 做两次后概率只能在 0.5 到 0.731 之间，背景像素的损失下限是 0.6931，前景占 0.32% 时整图损失下限 0.6919，阈值 0.5 下整张图都是前景。原句改成“损失根本降不下去”。
5. 12.5 原文把“加入平滑项”列为 Dice 的空类策略之一。用参考实现算：空掩膜、整张图 logit 为 -12、eps 取作业默认的 1e-6 时损失是 1.0（验收脚本里 4×4 的例子是 0.9899），logit 降到 -20 才是 0.8941；eps=1 时同一预测是 0.0245。也就是默认的 eps 并不能让“空对空”得到接近 0 的损失。原句改成“加入大小合适的平滑项（取多大差别很大）”。
以下几条原句没有改，在后面补了实测：
6. 12.7 原文“对 mask resize 必须用最近邻插值”。最近邻不制造新类别，但缩小时会丢小目标：边长缩到 1/4，1×1、2×2、3×3 的方块缩小后还在的比例是 5.2%、26.6%、60%（理论值 6.2%、25%、56.2%）。
7. 12.5 原文“先用可解释的 CE/BCE+Dice 建立基线”。实测前景占 0.31%、训练 300 步：交叉熵加 Dice 三个种子的 Dice 是 0、0.954、0.914，有一个种子和纯交叉熵一样卡在全背景；只用 Dice 是 0.948、0.952、0.967。只有 3 个种子，讲义里写的是“在这组实验里不如只用 Dice”，没有下一般结论。
8. 12.3 骨架里用了 BatchNorm2d。实测批大小 8 时，同一份权重在推理模式（滑动平均）下 Dice 0.794，用训练集重新统计均值方差后 0.976；三个种子五个评估时刻里推理模式在 0.794 到 0.989 之间跳，重新统计后在 0.965 到 0.99。讲义在骨架后加了指向 12.8 节的一句。
9. 12.9 原文把“连通域删除极小噪点”等列为后处理。实测 3×3 方形开运算把半径 1 px、1.5 px 目标的 Dice 从 0.892、0.964 降到 0、0.044，全部像素合起来的 Dice 只从 0.984 降到 0.922；面积过滤门槛取 5 个像素时半径 1 px 的目标降到 0.053。
10. 开头的“配套练习：DL-9 U-Net 细胞分割”指向一个目录里没有文件的练习。按第 4 章的做法保留原句，补了一段说明自动验收的作业是 作业_Dice与跳跃连接.py，DL-9 的题目在 视觉算法学习计划.md。

新增的重要结论：
1. 前景占 0.31% 时只用交叉熵训练 300 步，三个种子在阈值 0.5 下的 Dice 是 0、0.887、0，卡住的两个像素准确率 99.69%；把阈值降到 0.25 和 0.3，这两个网络的 Dice 是 0.868 和 0.918。它们缺陷像素上概率的中位数（0.43、0.448）正好等于输出层偏置过 sigmoid 的值，40.1% 和 54.8% 的缺陷像素在输出层之前 8 个特征全为 0。再训练到 600 步是 0、0.925、0.915。全背景常数预测的交叉熵在前景占 0.32% 时只有 0.0214，是初始损失的 3.1%。前景占 4.77% 时三种损失 150 步后都不低于 0.948。
2. 同样偏 1 px，半径 2 px 的目标 Dice 是 0.684，半径 20 px 的是 0.968；偏 2 px 是 0.387 对 0.936。同一批预测，全部像素合起来算是 0.985、逐图平均是 0.95（没有跳跃连接时 0.942 对 0.866）；什么都不预测时，按“空对空记 1”逐图平均是 0.286，正好是空图的比例。
3. 去掉跳跃连接，全部像素合起来的 Dice 只从 0.984 降到 0.934，半径 1 px 的目标从 0.892 降到 0.648，边界带（真值边界内外各 1 px）里的错误率从 2.0% 升到 8.5%。
4. 把 BatchNorm 换成 GroupNorm（2 个种子）：同分布测试集上 Dice 0.961、0.963，但 40 张没有缺陷的图里有 40 张和 38 张出现误报（BatchNorm 是 2、0、0）；切块推理多读 32 px 上下文后仍有 181 个像素和整图推理判定不同。

没有验证或拿不准的地方：
1. 训练实验的规模很小：一个 27721 参数的 U-Net（通道 8、16、32，两次下采样），批大小 8，Adam 学习率 0.003，每组 3 个种子（GroupNorm 对照只有 2 个），96 张训练图。所有关于损失、跳跃连接、归一化的结论只在这一组设置下测过。
2. 损失对比的结论依赖归一化的选择，这一点讲义里没有展开。探索阶段（不在最终脚本和 JSON 里）试过别的归一化：不加归一化时（用的是另一版数据），前景占约 4.7% 的那组只用 Dice 训练，三个种子里有两个塌成全前景或全背景；用 GroupNorm 时（数据和最终脚本相同），交叉熵在前景占 4.8% 的那组也有一个种子卡住（最大概率 0.494）。也就是说“只用 Dice 最稳”在别的归一化下不成立。讲义只报告了 BatchNorm 加重新统计这一种设置的结果，并写了“只有 3 个种子，不能据此说哪种损失更好”。
3. 所有训练实验在评估前都用全部训练图把 BatchNorm 的均值方差重新统计了一遍（讲义开头的说明框、12.8 节和 JSON 的说明里都写了）。不这样做，同一组数字会像 12.8 节的表那样跳。这不是普通训练循环的默认做法，读者照普通做法复现时数值会不一样。本章 Notebook 里的小网络没有归一化层，不受影响。
4. “交叉熵为什么卡在 0.5 以下”的解释是从两个卡住的种子的统计量推出来的（最大概率约等于 sigmoid(偏置)，缺陷像素特征全 0 的比例，背景像素 99.99% 的 logit 低于偏置）。没有做干预实验（例如改偏置初始化、换更宽的网络）来验证因果。“背景像素给偏置的梯度方向往下”是按公式说的，没有量。
5. 平滑项 eps 只做了“构造 logits 直接算损失和梯度”的数值实验，没有训练对比。探索阶段在“每三张图一个缺陷”的数据上试过 eps 取 1e-6、1、100 各 3 个种子，种子之间的差别大于 eps 之间的差别，得不出稳定结论，所以没写进讲义。讲义里“很小的 eps 等于让空图不参与 Dice 这一项”“小目标上 Dice 损失会一直把背景概率往 0 推”是从损失值和梯度大小推出来的，不是训练结果。
6. 前景占 4.77% 那组只训练了 150 步，前景占 0.31% 那组 300 步，为的是把脚本压在时间限制内。两组不是同一步数，表头和图标题里写了。
7. “逐个目标的 Dice”是我自己定的口径（只看目标周围 2 px 以内的预测），不是标准指标；“边界带里的错误率”也是。Boundary IoU、Hausdorff 距离没有测。
8. 图 2 左边的示例图不是随机挑的，取的是两种网络逐图 Dice 之差排第 10 大的那张测试图，图注里写了。
9. 切块实验只用了 1 个网络（种子 0）和 2 张图；加权平均只试了“权重等于到块边的距离”这一种；起点不对齐只测了 (34, 34) 一个位置（最大概率差 0.14）。GroupNorm 的切块结果也只有种子 0。
10. 显存一节只统计了前向时中间张量的元素个数（64×64 输入时是参数量的 24.8 倍，原分辨率一级占 62.5%），没有量过实际占用的字节数。`torch.cuda.*` 的代码片段、混合精度、梯度累积、按含缺陷比例采样小块这些建议都没有在这台机器上运行过（没有 CUDA）。
11. GroupNorm 在空图上误报的原因，讲义写的是“一个说得通的解释……没有单独验证”。训练集里放进空图之后是否还这样，没有测。
