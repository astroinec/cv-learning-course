# 写作规范：每章怎么写

> 给维护者和接手的 AI 助手。第 16 章是按本规范写成的样板，动手前先通读一遍第 16 章。

## 1. 一章的固定结构

讲义只有一份：章节目录里的 `教程_*.md`。它在 GitHub 上直接可读，`scripts/build_site.py` 再把它转成网页。不要另写一份网页版。

| 小节 | 必须有的内容 |
|---|---|
| 0. 本章怎么学 | 应用场景、优先级、前置章节；速通、标准、深挖三档的累计用时、做什么、做到什么算完；超时规则提示 |
| 1. 为什么需要 | 用一个能量化的实验说明“不学这个会出什么问题”，给一张图和一张表 |
| 中间各节 | 直觉 → 推导 → 实测 → 工程细节。每个关键结论后面跟一张图或一张表 |
| 交互演示 | 嵌入 `demos/` 里的一个页面，带“按顺序试”的引导步骤 |
| 怎样评估 | 这一类方法的精度或效果该怎么测、怎么报告 |
| 常见错误 | 现象、原因、怎么查三列的表 |
| 破坏实验 | 先预测再运行，前三个是标准档必做 |
| 扩展 | 深挖档的内容，可以用外部库和真实数据 |
| 和后续章节的关系 | 前后各指出一两章 |
| 自测问题 | 5 到 7 道，速通档答小测，标准档答自测问题 |

每章 3 到 5 道小测，放在对应小节末尾。

## 2. 数字和图

1. **讲义里的每个数字都要能复现**。配图和数字由 `solutions` 分支的 `solutions/figures/chNN.py` 生成，写到主分支的 `NN_*/figures/`，同时输出 `实测数字.json`。改讲义里的数字之前先重跑脚本。
2. 配图脚本放在 `solutions` 分支，因为它要调用参考实现。主分支只放生成好的 SVG 和 JSON，不泄露答案。
3. 每张表的表头或上一句话写清实验条件：图像尺寸、噪声、重复次数、随机种子范围。
4. 实测结果和直觉不一致时，以实测为准，并把这个反差写进讲义。第 16 章里“相位相关在周期图案上限制搜索范围仍然失败”就是这样来的。
5. 配图统一用 `solutions/figures/_style.py`：中文字体、配色、`constrained` 布局、SVG 输出。生成后用 `FIG_PREVIEW_DIR=/tmp/xx` 另存 PNG，逐张看一遍有没有重叠和缺字。
6. 配图按讲义里出现的顺序编号。图的标题写的是结论，结论必须能从图上或同一节的表里直接看出来；看不出来就改图的画法（例如第 17 章图 4 把残差按位置取平均），或者改标题。
7. 理论数值（高斯尾概率、置信区间之类）也由脚本算出并写进 `实测数字.json`，不手算。

运行方式：

```bash
# 在 solutions 分支的工作树里
COURSE_MAIN_DIR=../cv-learning-course ../cv-learning-course/.venv/bin/python solutions/figures/ch16.py
```

## 3. 讲义里的扩展写法

以下写法在 GitHub 上能正常显示，网页构建时会转成交互组件。

**提示框**（GitHub 原生语法）：

```markdown
> [!NOTE]
> 说明文字。
```

可用 `NOTE`、`TIP`、`IMPORTANT`、`WARNING`、`CAUTION`。

**公式**：行内 `$...$`，独立一行 `$$...$$`。公式里有换行符 `\\` 时（矩阵、多行对齐），改用 ` ```math ` 围栏，否则 GitHub 可能把 `\\` 当成转义吃掉。网页用随仓库附带的 KaTeX 渲染，不联网。

**配图**：`![图 N：一句话说清图里看什么](figures/xxx.svg)`。方括号里的文字同时是图注。

**小测**：

```markdown
<!-- quiz -->
**题干？**

- A. 选项
- B. 选项
- C. 选项

<details markdown="1"><summary>答案与解释</summary>

**B**。解释为什么，也解释错误选项错在哪。

</details>
<!-- /quiz -->
```

答案字母必须加粗写在折叠块的第一个词。网页上点选项会显示对错和解释。

**嵌入演示**：

```markdown
<!-- embed: ../demos/相位相关.html 1010 -->
[打开交互演示：相位相关与亚像素](../demos/相位相关.html)
```

数字是嵌入框高度（像素）。下面那行链接是给 GitHub 读者的。

## 4. 交互演示

1. 单个 HTML 文件，不引用任何外部脚本或字体，离线可用。
2. 计算逻辑和作业里的算法一致，可以降维（例如二维换一维）以便实时计算。
3. 页面下方给“按顺序试”的 3 到 5 步，每步带“载入”按钮，一步对应讲义里的一个结论。
4. 写完后用 node 直接执行页面里的计算代码，核对每一步引导语描述的现象确实会出现。

## 5. 时长与优先级

- `course.json` 是唯一的数据源：每章的应用场景、优先级、三档用时、前置章节，以及首页的学习路线。首页、侧栏、章节页头都由它生成。
- 三档用时是累计值：标准档包含速通档，深挖档包含标准档。
- 优先级含义：P0 入职第一个月就会用到；P1 主线能力；P2 分到对应方向再学；P3 已有基础或用得少。
