# 单章升级任务说明

> 给接手“把一章升级到新标准”的助手。多个助手会同时在同一个仓库里各改各的章，所以文件归属和禁止事项必须严格遵守。动手前先读完本文件，再读 `docs/写作规范.md`，然后通读一章样板讲义和它的配图脚本（第 17 或 18 章）。

## 1. 目标

课程的唯一读者是仓库主人自己：有本科基础、会编程，目标岗位是半导体检测方向的视觉算法工程师，用一台带 RTX 4060（8 GB 显存）的 Windows 笔记本学习。他给的要求是：

- **不减只增**。原讲义的内容都保留，在它的基础上加深。原讲义说错的地方改掉，并在回报里写明改了什么。
- **每章开头说明应用场景和优先级，给三档用时**，方便他自己挑着学，不会卡在某一章出不来。
- **理论和实践并重**，结论要有图或表支撑，呈现形式尽量好（配图、公式、小测、交互演示）。

升级后的一章要达到第 16、17、18 章的水平。完成的判据是第 4 节的自检脚本通过，并且第 5 节的每一条都做到。

## 2. 文件归属

两个工作目录：

- 课程仓库：`<课程仓库>`（分支 `upgrade/site`）
- 参考答案工作树：`<参考答案工作树>`（分支 `upgrade/solutions`）

负责第 NN 章的助手**只能**写这些文件：

| 文件 | 说明 |
|---|---|
| `NN_*/教程_*.md` | 讲义。第 24 章没有讲义文件，新建 `教程_综合项目.md`，README 保留 |
| `NN_*/README.md` | 只改用时那一句和文件表（加上 `figures/` 和演示页两行） |
| `NN_*/figures/` | 配图 SVG 和 `实测数字.json`，全部由脚本生成 |
| 参考答案工作树的 `solutions/figures/chNN.py` | 配图脚本，新建 |
| `demos/<新文件名>.html` | 需要新演示时新建一个文件，不能改已有的演示页 |

**不能动**的东西：

- 本章的作业文件、`tests/`、`data/`、Notebook、`实验记录.md`，以及参考实现本身。发现它们有错，写在回报里。
- 所有共享文件：`course.json`、`docs/`、`scripts/`、`site/`、`AGENTS.md`、根目录的各种说明、`solutions/figures/_style.py`、已有的 `demos/*.html`。需要改它们时写在回报里，由统筹的人合并。
- 其他章的任何文件。
- **任何会改变仓库状态的 git 命令**：`add`、`commit`、`stash`、`checkout`、`switch`、`restore`、`reset`、`clean`、`merge`、`rebase`、`push` 一律不用。别人的改动和你的在同一个工作目录里，这些命令会毁掉别人的工作。只读命令（`status`、`diff`、`log`、`show`）可以用。
- 不运行 `scripts/build_site.py`（它写共享的 `site/`），用第 4 节的自检脚本代替。
- 不装包、不升级包。虚拟环境是共用的。
- 不启动网页服务，不使用浏览器工具（只有一个浏览器，会互相抢）。
- 探索用的临时脚本和预览图放 `/tmp/chNN_*`，不要留在仓库里。

## 3. 步骤

1. **读**：原讲义、本章全部作业文件、`tests/check_progress.py`、参考实现（`solutions/NN_*/`）、本章 Notebook 里的实验（第 16 到 24 章的 Notebook 内容在 `scripts/build_track2_notebooks.py` 里）、`course.json` 里本章的条目（场景、优先级、三档用时、前置）。
2. **先测再写**：在 `/tmp` 里写探索脚本，对原讲义里每一条可以量化的结论做对照实验。重点找“原讲义这么说，实测不是这样”的地方，前三章每章都找到了两三处，这是升级里最有价值的部分。
3. **写配图脚本** `solutions/figures/chNN.py`：照 `ch17.py`、`ch18.py` 的结构，用 `_style.py`，调用参考实现（`S.load_solution`），每组实验把条件和结果写进 `NUM` 字典，最后输出 `实测数字.json`。5 到 6 张图。
4. **看图**：用 `FIG_PREVIEW_DIR=/tmp/chNN_preview` 另存 PNG，逐张打开检查缺字、重叠、图例遮挡，以及标题里的结论能不能从图上看出来。
5. **写讲义**：按 `docs/写作规范.md` 第 1 节的结构。每写一个数字，回到 `实测数字.json` 核对。
6. **演示**：嵌入一个交互演示。已有的演示页合适就直接嵌入；否则新做一个（样式和结构照 `demos/相位相关.html`）。
7. **改 README**：用时一句和文件表。
8. **自检**：第 4 节。
9. **回报**：第 8 节。

## 5. 必须做到的事

1. **第 0 节**用 `course.json` 里的场景、优先级、前置和三档用时，表格照第 17 章。每一档写清“做什么”和“做到什么算完”。带上超时规则的提示框。
2. **讲义开头**有一个说明框，写明数字来自 `figures/实测数字.json` 和哪个脚本，换成真实数据要自己再测。
3. **讲义里的每个数字**都能在 `实测数字.json` 里找到，或者由里面的数字做一步简单换算得到（百分比、倍数）。理论数值也由脚本算出来写进 JSON，不手算。
4. **每张表**的表头或上一句写清实验条件：尺寸、噪声、次数。
5. **配图**按讲义里出现的顺序编号，文件名 `figNN_主题.svg`，图注格式 `![图 N：……](figures/figNN_xxx.svg)`。图注描述图里每一栏画的是什么。
6. **图的标题和讲义里的断言必须能从图或表里直接看出来**。看不出来就改画法，或者把话说得弱一些。不要写图上看不出来的方向、趋势和因果。
7. **3 到 5 道小测**，放在对应小节末尾。题目考“反直觉的实测结论”，不考定义背诵。解释里引用具体数字。
8. **常见错误**表三列：现象、原因、怎么查。至少包含做本章作业时最容易犯的几个实现错误。
9. **破坏实验** 5 到 6 个，先预测再运行，前三个是标准档必做。**扩展**一节是深挖档的内容。**和后续章节的关系**前后各指一两章。**自测问题**保留原有的并补到 5 到 7 道。
10. **不泄露作业答案**。讲义可以讲思路、公式和容易错的点，不贴作业函数的完整实现。配图脚本放在参考答案工作树里就是这个原因。
11. **原讲义的内容都在**。写完后把原讲义（`git show HEAD:路径`）的小节标题逐个对一遍，确认没有丢。
12. **配图脚本**固定随机种子，整个脚本在这台机器上 5 分钟内跑完，重复运行结果相同。

## 6. 前三章踩过的坑

- **先看数字再定结论**。写图的标题之前先把数字打印出来看。第 17 章原计划写“残差有方向规律”，画出来看不出来，改成按位置取平均才看得见。
- **实测和原讲义不一致时以实测为准**，并且把这个反差写成讲义的一个要点。但只说测到的条件下成立，不外推。例如第 17 章只写“用 SVD 求解时 float32 在这组实验里没有差别”，不写“float32 没有影响”。
- **一次实验的现象不要写成一般规律**。第 17 章里某一次标定焦距偏大 6%，但 100 次里偏差从 -2.3% 到 +7.5% 都有，讲义里两个数都要给。
- **批量替换之后重新核对数字**。第 18 章用正则给图重新编号时，把“每张图 47 个”里的“图 4”也改了。
- **领域事实要留余地**。具体到某家公司、某台设备、某条产线的做法，课程里查不到依据的就不写，或者写“以设备和公司的资料为准”。不编造厂商、型号、指标。
- **引用别的章之前先打开那一章确认**。第 18 章初稿写“第 22 章讲平场校正”，实际第 22 章没讲。
- **引用演示页的内容之前先打开它确认**，按钮名称、步数、标题都以页面为准。
- **中文字体缺字**：图里的减号用 ASCII 的 `-`，不要用 `−`。上标、不等号、希腊字母这类符号，生成后在 PNG 里确认没有变成方块。
- **图例遮挡曲线**时把图例放到坐标轴下方：`loc="upper center", bbox_to_anchor=(0.5, -0.2), ncol=2`。对数轴手动给刻度标签并 `minorticks_off()`。
- **含 `\\` 的多行公式**（矩阵、对齐）用 ` ```math ` 围栏，单行公式用 `$$`。
- **演示页**右栏用 `grid-template-columns: 320px minmax(0, 1fr)` 之类可收缩的写法，嵌入讲义时宽度只有 860 px 左右，不能出现横向滚动条。不引用任何外部脚本、字体、图片。写完用 node 执行页面里的计算代码，核对每一步引导语描述的现象确实出现。

## 7. 环境

- Python 用课程仓库的 `.venv/bin/python`。可用的库：numpy、matplotlib、opencv-python（5.0）、torch、torchvision、pillow。**没有** scipy、scikit-image、scikit-learn，需要的函数用 numpy 自己写。
- 这台机器是 Apple 芯片的 Mac，没有 CUDA。深度学习章节的实验用 CPU 跑，规模要小（几十秒到一两分钟），脚本开头 `torch.set_num_threads(2)`、固定种子。讲义里出现的训练耗时只能写“在一台 Mac 的 CPU 上实测”，**不能写 4060 上的数字**，因为没有测过。可以说明代码在有 CUDA 时会自动用 GPU。
- 不联网下载大文件。本章原有的 Notebook 或作业已经用到的 torchvision 小权重（例如 ResNet-18）可以下载；其他预训练模型不下载，实验设计成不依赖它们。
- 有 `g++` 和 `clang++`，没有 `cmake`。有 `node`。

## 9. 第一批（11 章并行）之后补充的规则

1. **会波动的测量要钉住**。耗时这类每次运行都不一样的数，用 `_style.py` 里的 `S.pinned(CH, "键名", measure, "CHNN_RETIME")` 包起来：默认沿用 `实测数字.json` 里上次的值，设置环境变量才重测。讲义里引用耗时只写两位有效数字，并写明是在哪台机器、什么条件下测的一次结果。第 15 章第一版把几十个耗时写到三位有效数字，统筹的人重跑脚本后全部对不上。多个助手同时跑时机器很忙，耗时比平时大，不要拿耗时的绝对值下结论，只用量级和明显的倍数关系。
2. **SVG 的元素编号已经在 `_style.setup()` 里固定**，不用自己设 `svg.hashsalt`。写完后把脚本连跑两遍，确认 `figures/` 下所有文件逐字节相同。
3. **回报写进文件**。完成后把第 8 节格式的回报写到 `/tmp/wave2/report_NN.md`，最后一条消息只回一行：“第 NN 章完成，自检通过/没通过，回报在 /tmp/wave2/report_NN.md”。
4. **演示页的版面你看不到**，统筹的人会用无界面浏览器量实际高度、查横向溢出和脚本报错，嵌入高度先按估计写。你要保证的是：计算代码用 node 核对过；布局用可收缩的写法；“按顺序试”每步有“载入”按钮。
5. **演示页脚本里可以有和作业等价的算法实现**（要实时计算就免不了），讲义正文不贴作业函数的实现。这一条已定，不用再问。
6. **第一部分各章的标题**：原标题文字保留，可以在后面加括号补充，例如“常见坑与排查顺序（常见错误）”“动手前的检查清单（自测问题）”，这样自检脚本能认出来。
7. **原讲义指向不存在的练习文件**（例如 `4-2_图像拼接.py`）是普遍问题：实际的自动验收作业以章节目录里的文件为准，其余题目在 `视觉算法学习计划.md` 里，按第 4、5 章的改法处理。
8. **核对讲义数字**：写完后运行 `.venv/bin/python scripts/audit_numbers.py NN`，它列出讲义里在 `实测数字.json` 找不到出处的数。逐个确认：是两个 JSON 数一步换算出来的可以留，其余的要么写进 JSON，要么删掉。
9. **本机没有任何数据集缓存**（没有 CIFAR-10、MNIST、COCO），也没有 ultralytics、timm、onnx、onnxruntime、scikit-learn。深度学习各章的实验用代码生成的小数据在 CPU 上做，单个脚本 5 分钟内跑完。只有 ResNet-18 的 ImageNet 权重在本机有缓存，可以用。原讲义里提到的数据集和库保留原样，属于“学员在自己机器上做”的内容，讲义里不要出现你没跑过的精度数字。
10. **读者的显卡是 RTX 4060（8 GB）**，但这台机器没有 CUDA。深度学习各章要告诉读者怎样在自己机器上确认显卡可用、怎样看显存占用、批大小不够时怎么办，这些写通用做法；参数量、单次前向的计算量、CPU 上的实测耗时可以量。任何“在 4060 上要多久、占多少显存”的数字都不能写。
